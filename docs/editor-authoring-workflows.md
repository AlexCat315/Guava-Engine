# 编辑器创作工作流与 Agent 工作台

编辑器采用三个独立概念：创作领域决定功能范围，任务工作流决定当前工具组合，交互模式决定用户如何发起和检查修改。停靠布局只是手动编辑模式下的显示偏好。

| 创作领域 | 任务工作流 | 当前功能范围 |
| --- | --- | --- |
| 游戏开发 | 关卡编辑、脚本开发 | 场景、渲染、动画、模拟、游戏组件、脚本与游戏构建 |
| 3D 创作 | 建模与渲染 | 场景、资源、材质、灯光、相机与渲染 |
| 3D 创作 | 动画制作 | 共享场景与渲染能力，加动画及制作所需物理模拟；排除游戏控制器、游戏脚本和游戏构建 |

当前工作流沿用 `EditorWorkspaceMode`，其 `EditorWorkspaceProfile` 统一提供领域、功能和内置面板范围。工具栏明确显示领域和任务，手动编辑与 Agent 是另一个独立选择。菜单、命令搜索、命令执行、面板注册视图、检查器组件和视口物理调试都使用同一范围规则。用户切换范围不会删除场景已有的组件。

## 状态与界面

`EditorWorkspaceState` 持有工作流、布局预设和交互模式，直接作为完整分组写入编辑器外壳设置。读取缺失字段使用拥有者的默认值，不属于当前工作流的预设会归一化为该工作流的默认预设。当前格式统一为 `workspace` 分组，不保留旧的平铺工作区字段。

手动编辑继续使用现有 `PanelWorkspace`。Agent 工作台以任务列表、场景预览、对话及待确认结果为主要区域，使用同一个 `EditorApplication` 和场景。切换界面保留文档身份、选择和手动停靠布局，不重新创建场景。Agent 的确认面板复用现有事务确认流程。

窗口顶部只放全局菜单，领域、任务、布局、游戏播放和交互模式集中在一条工具栏内。Agent 预览直接显示视口，不重复工作流标题；3D 创作没有单项“场景编辑”页签，游戏工作流仍保留“场景编辑 / 游戏预览”切换。

进入项目后，主窗口就绪时执行一次最大化；既覆盖命令行直接打开项目，也覆盖欢迎页打开项目。关闭项目恢复窗口尺寸，欢迎页保持原有窗口行为。

## 任务与能力范围

`EditorAgentTaskService` 管理任务生命周期和只读任务列表；请求句柄、协程、方案和确认目标属于独立的临时执行状态。任务列表与文档身份不持久化为场景或用户设置。当前每个编辑器实例只运行一个待规划或待确认任务，保留最近 40 条会话任务。

提交任务时捕获文档身份、创作版本、工作流和选择。模型调用前、返回方案后及确认执行前检查目标。切换选择不会把任务改到另一个实体；切换工作流不会扩大已提交任务的能力。手动修改使旧方案过期，用户可以放弃；新建或打开文档会取消旧任务。这里比较的是创作文档版本，运行时渲染提取的版本变化不构成用户修改。

`SessionWorkflowScope` 将工作流上下文、允许的能力 ID、项目工具名称和选择引用传给 AI Runtime。能力发现、提供方工具定义、实际工具调用与选择提示使用捕获的范围；它与既有权限策略取交集。启用插件仍受原有权限规则约束。建模工作流不能通过项目工具调用游戏构建或写游戏脚本。

MCP 使用同一配置收窄能力暴露。当文档身份或能力范围变化时，旧的发现会话与草稿失效，避免另一个文档恰好使用相同数值版本时复用旧操作。

AI 修改仍由现有事务执行器提交，并进入同一编辑历史。手动编辑、确认 AI 方案、撤销与重做不维护第二份场景或历史。

## 后续文档模型

这一阶段建立功能边界和交互外壳，已有资源导入、组件编辑与渲染继续工作。建模工作流目前没有网格顶点、UV、骨骼编辑器；动画工作流也没有独立镜头序列时间线。界面与 AI 上下文不会声称提供这些工具。

后续应分别引入资源文档和序列文档：网格与 UV 操作属于资源文档；镜头、轨道、关键帧与输出属于序列文档；游戏场景继续管理实体、运行时组件与游戏构建。各文档提供自身事务和检查器描述，渲染、资源索引及 AI 任务服务保持共享。不要把这些功能继续堆入场景组件或停靠预设。

## 验证

Editor 的回归覆盖领域菜单与命令、面板布局、Agent 预览内部尺寸、状态分组序列化、任务固定目标、过期方案拒绝、新文档取消任务，以及 AI 与手动修改共用撤销历史。Engine 的回归覆盖三种提供方工具格式、能力范围交集、固定选择、MCP 会话失效和创作上下文序列化。原生窗口另行检查最大化、实际视口拉伸和欢迎页尺寸恢复。
