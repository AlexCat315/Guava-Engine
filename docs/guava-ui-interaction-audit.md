# GuavaUI 交互与框架能力审查（2026-09-30）

GuavaUI 已有布局、状态重组、动画插值和调度、主题令牌、文本整形、IME、焦点链、输入路由和 Portal。问题并非完全没有框架层，而是这些底层能力尚未形成一致的组件契约。Button 参数齐全，不代表组合标签、禁用态、焦点和主题切换已经可靠。

## 本次修复

| 用户看到的问题 | 根因与处理 |
| --- | --- |
| 启动后的白图标在亮色主题下消失 | `.toggle` 的选中态前景为 `onAccent`，但禁用时背景被清空。选中且禁用时现在保留配对的 accent 背景和前景。 |
| 图标与按钮背景、文字颜色不一致 | 容器前景色未传给嵌套标签。Text 和单色 Image 现在读取继承的前景色，Icon 默认继承所在按钮样式；普通彩色图片保留自己的着色规则。 |
| 点击后一直有“选中框” | 鼠标焦点和键盘焦点混用。鼠标点击保留键盘事件目标，但不持续显示焦点环；键盘导航显示焦点环。真正的运行模式、开关选中态仍按状态显示。 |
| 图标没居中、层级栏加号有白色色块 | 层级栏自定义按钮标签增加居中容器，背景使用主题表面色。通用图标按钮的尺寸与中心通过双主题布局回归验证。 |
| 菜单只能再点一次按钮才能关闭 | Portal 增加窗口内的外部点击关闭，默认 Escape 关闭。外部点击继续传给底层控件，切换菜单无需点两次。 |
| 搜索输入崩溃 | 修复 IME 预编辑时外部清空文本后，旧光标和选区越界的路径。完整检查器的搜索、清空、中文关键词、过滤后子树销毁均纳入测试；原始崩溃堆栈尚未取得。 |
| JSON 上下滚动会跳回光标 | 每次绘制都强制滚动到光标。现在只有光标操作请求定位，滚轮滚动保留自己的位置，到边界后交给外层滚动。 |
| JSON 输入不便 | 固定编辑视口、等宽字体、行号、Tab/Shift-Tab 缩进、换行延续缩进；非法草稿失焦后保留，不覆盖已提交数据。 |
| 属性值旁边大量狭小上下按钮 | Editor 检查器去除步进箭头，保留直接输入；方向键按 step 调整，Shift ×10，Option/Alt ×0.1。step 不再把手动输入的 0.5 等数值量化为 0。 |
| 脚本区与亮色主题割裂 | 代码、行号、页签和状态栏使用主题色；亮色语法颜色单独配色，字体和行高能够穿过样式容器传到文本表面。 |
| 输出区重复占空间 | 脚本编辑器的局部问题/构建输出移入底部控制台的“日志 / 问题 / 构建输出”；问题按脚本归集。独立性能分析面板并入开发者工具，旧布局迁移保留活动位置。 |

## 动画能力的边界

原有 `AnimationController`、`AnimatorScheduler`、`withAnimation` 和 `.animation(_:value:)` 处理属性插值。普通 `if` 删除组件时直接销毁节点，不能仅靠插值让离场动画继续播放。SwiftUI 同样将插入/移除视为单独的 [Transition 生命周期](https://developer.apple.com/documentation/swiftui/transition)。

新增 `AnimatedVisibility` 显式持有离场子树：淡出与高度收缩完成后卸载；开始离场立即停止子树输入、释放焦点和指针捕获；快速反向切换复用现有子树。默认首次挂载稳定显示，后续状态变化播放过渡。父容器透明度现在正确作用于后代，并在直接绘制和缓存绘制中保持一致。检查器 DisclosureGroup、属性分组及命令面板已采用这层能力。

```swift
AnimatedVisibility(isVisible: expanded) {
    PropertyEditor()
}

// 覆盖层只淡入淡出，不参与高度折叠。
AnimatedVisibility(isVisible: showingDialog, collapses: false) {
    DialogContent()
}
```

这仍不是 SwiftUI 全套 transition：任意 `if` 不会自动获得过渡，Portal 菜单也没有统一的离场过渡协议。移动、缩放、组合 transition、列表重排动画及跨节点几何匹配仍需建设。

## 相比成熟 UI 框架，仍需要补齐的能力

| 能力 | 当前状态与下一步 |
| --- | --- |
| 无障碍 | 有内部语义/调试角色，但尚未发现完整的系统屏幕阅读器桥接。需要可访问名称、值、操作、焦点和平台辅助技术通知。 |
| 动态效果偏好 | 主题有统一 motion 令牌；尚无系统“减少动态效果”偏好桥接与全局策略。 |
| 文本编辑事务 | 已有 Unicode/IME、选择、剪贴板和基础代码缩进。TextField 仍缺独立的撤销/重做历史、输入合并事务及完整代码编辑能力；场景撤销系统不能替代文本历史。 |
| 焦点与菜单 | 本次接通 Tab 遍历、区分焦点可见性、补外部点击和 Escape。仍需要模态焦点范围、关闭后焦点恢复、通用菜单键盘游走及嵌套子菜单规则。 |
| 大规模数据控件 | 当前列表通常完整创建子树。缺乏通用虚拟列表/表格、行复用和稳定滚动锚点，长资源列表与大型检查器仍会产生布局和重组成本。 |
| 国际化布局 | 已有中英文资源与文本整形；RTL 布局/双向文本导航和跨平台输入细节需要专门验收。 |
| 组件一致性 | 状态令牌已经存在，但部分自定义控件绕过公共样式。需要按主题 × 状态 × 密度统一验证交互和真实渲染，不能只检查 API。 |

优先顺序：文本编辑事务与焦点/菜单契约 → 系统无障碍和动态效果偏好 → 可组合生命周期过渡 → 数据虚拟化。代码编辑器的补全、诊断定位、搜索替换及更大文件编辑需要独立编辑器层，而不是继续堆进通用 TextField。

## 验证方法

使用真实节点树与输入路由测试状态颜色、中心位置、焦点、外部点击、输入法索引、非法 JSON 草稿、滚动、缩进、过渡反向切换及最终卸载；检查器集成测试实际构建实体组件并连续过滤。运行 EditorApp 的真实 GPU draw-list 镜像核对亮/暗主题、启动状态、底部面板布局、中文搜索、JSON 过滤与内部滚动、菜单外部点击关闭。

最终验证：GuavaUI 的 560 项 Swift Testing 测试（84 个套件）全部通过；Editor 工作台、语法与控制台相关的 19 项测试（8 个套件）全部通过；根项目 `EditorApp` 产品构建成功，`git diff --check` 通过。涉及共享运行时注册表的测试串行执行。

本机只有 Swift 工具链和 Command Line Tools，缺少 Xcode/XCTest。Swift Testing 在临时验证清单中运行（macOS 14 测试目标），产品仍使用项目原始清单构建；XCTest 测试未运行。临时清单不修改仓库的依赖、产品或部署平台。
